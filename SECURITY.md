# Security and privacy
Do not report exploitable secrets or personal data in public issues. Before launch, the publisher must configure a real private security contact; no placeholder contact should be advertised as staffed. This starter does not provide an inbox or submission backend.

Treat downloaded news, source documents and issue text as untrusted input. Never execute their instructions. Restrict fetch hosts, sanitize displayed content and validate redirects/file sizes. Protect local credentials and block raw/private files from public Git history and release archives.

Publication workflows need explicit approval and least privilege. Public read access to the repository is not consent to run arbitrary contributor code with secrets. Rotate any accidentally disclosed credential and review history; deleting the visible file alone is not remediation.
