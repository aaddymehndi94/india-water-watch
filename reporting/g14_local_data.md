A build dated 24 September does not make those older observations fresh. A small same-product, same-period *state contrast* is feasible from the state map after rights/editorial review, but a synchronized district feature is not yet feasible from these endpoints.

Caption it “IMD cumulative rainfall, 1 June–24 September 2026, against IMD's displayed normal”; state that the precise normal reference years are **not identified on the state page**. Because the source page is copyrighted and lacks an explicit bulk-reuse licence, the rights-safe near-term editorial choice is a **small number of attributed facts** with direct links to the original IMD page and original chart design, not a mirrored 36-row dataset, IMD map geometry, raster screenshot, or full tooltip text. Legal/publisher rights review remains appropriate for full-table republication.

## Reproducible candidate transform and checks

1. GET only the exact HTTPS state URL above; reject redirects, non-HTML, overlarge bodies and unexpected host. Save an ignored local raw HTML with retrieval timestamp, byte count and SHA. Never execute scripts from it.
2. Require an exact cumulative date label with start and end, then JSON-decode the embedded `dataProvider.areas` array (the same constrained structure used by `pipeline.sources.imd_cumulative`). Require 36 unique numeric state/UT IDs. Do **not** use a name-only join to the site's LGD geography. Retain IMD ID/name as source geography; crosswalk manually if the UI requires a canonical state route.
3. Parse `Departure : ...%`, `Actual : ... mm`, `Normal : ... mm` from each `balloonText`; remove thousands separators. Require complete triples or an explicit missing record, `normal_mm > 0`, nonnegative actual, and percent consistency within a tolerance for one-decimal rounded mm and whole-percent departure. At this snapshot all 36 numbered areas parsed and had unique IDs; no mismatch over 0.55 percentage point was found.
4. Exclude all nonnumeric-ID summary/legacy areas from state counts. If national figures are shown, cite the same-date national GIF separately and disclose its 0.1 mm disagreement with the map country row. Never average state percentages into a country departure or compare to regional GIF percentages as if the boundaries were identical.
5. Emit an **unapproved candidate** with `source_url`, `source_sha256`, `retrieved_at`, page date labels, nullable provider publication time, source geography namespace, normal-period status `unidentified_on_state_page`, per-row actual/normal/published departure and quality flags. Require source/method/rights review, then scoped claim approval before any public use. Later updates compare semantic values and observation labels; a changed HTML hash alone is not a new rainfall observation.

## Rights and temporal limits

The [IMD page disclaimer](https://mausam.imd.gov.in/responsive/disclaimer.php) says its real-time information can change without notice, and the site footer asserts copyright. The [IMD data-service page](https://dsp.imdpune.gov.in/home_freedataaccess.php) makes some historical all-India series freely accessible, while [IMD regional data-supply guidance](https://mausam.imd.gov.in/patna/mcdata/Data_Supply_Procedure%28ENGLISH%29.pdf) describes charged requests for other meteorological data. Neither establishes an open licence for mirroring the entire current state/district map dataset. No external permission or paid access was sought. Original downloaded GIF/PNG images are in ignored `artifacts/research/g14_local_data/` solely for source inspection, not public assets.

The current product check reveals **asynchronous provider publication**, not a reliable 24-hour rainfall increment. The 24 Sep national GIF and state map can be discussed on their own dated terms after review; the 23 Sep district and statistics images should remain visibly 23 Sep. No independent September 2026 groundwater or delivered-supply point suitable for this local rainfall graphic was established from CGWB. The already documented [January 2026 well PDF review](groundwater_public_claims.md) reports ambiguous well identities/date headings, a TLS verification failure for automated access, and no basis for district water-stock inference.
