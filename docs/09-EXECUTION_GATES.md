# 09 · Gates and deliverables

Gates are dependency controls, not repeated requests for user permission. The lead can pass technical gates after actual evidence. Publication authorization is separate. A failure in one data module does not stop safe work elsewhere.

## G0 · Environment and working agreement

Inspect repository, OS, Codex capabilities, network/browser access, available Node/Python/package manager and existing credentials without exposing them. Read official current compatibility docs; resolve and lock stable dependencies. Validate `.codex` format without changing global settings. Record versions in `state/TOOLCHAIN.md`. Establish ownership, secrets/rights exclusions and deterministic test commands.

**Evidence:** toolchain report, local repo status, scoped plan, source-access test, passing starter tests. No website or source claims may be called verified here.

## G1 · Evidence reset and source feasibility

Audit every inherited claim. Inspect exact primary products/archives where available, including observation cutoff and baseline. Build the source registry and initial geography/method contracts. Identify useful current measurements and a comparable historical core, plus legitimate fallback/manual-import paths.

**Evidence:** `prior-claims-audit.md`, current-source ledger, coverage plan, critical methodological decisions. It is acceptable to retire an inherited claim. Do not invent a national crisis assessment to pass this gate.

## G2 · Real end-to-end vertical slice

Build one working path from permitted raw source → validated normalized observations → reviewed claim → chart/table → local page → exact source drawer → downloadable CSV. Include one national or state context and one local view as supported by data. Implement real source failure and missingness behavior. Review a mobile screenshot.

**Evidence:** at least one inspected source product; adapter fixture and tests; independent calculation replay; meaningful chart and table; source locator; readable design; working local navigation. Synthetic values can test the implementation but cannot satisfy real-data evidence requirements.

## G3 · National atlas and comparable history

Implement all state/UT navigation from the verified inventory. Add district rainfall coverage where accessible and reliable; do not manufacture water-demand coverage. Build basin distinctions, geography crosswalks and coverage reports. Establish historical series/rank eligibility and same-cutoff comparisons. Handle split/renamed areas and no-data states.

**Evidence:** geographic join report, population-method notes, historical included/excluded year ledger, rank tests, map/table agreement, source dates and search aliases. Full district support means actual supported metrics, not a copied national paragraph per district.

## G4 · Journalism and explanatory depth

Investigate each editorial beat. Produce finished explainers for the well-supported topics and documented gaps for the rest. Integrate response stages, voices, history, inequalities, economic channels, practical information and recovery. Add forecasts/scenarios only under their own contracts. Research should be specific, sourced and readable, not a generic climate essay.

**Evidence:** claim-level source audit, counterevidence, no invented interviews/bylines, quote/rights checks, human-review queue for sensitive material, coherent narrative links to charts. Claims needing human reporting may remain withheld without blocking unrelated explainers.

## G5 · Repeatable update system

Implement adapters, candidate/approved snapshots, semantic diff, affected-claim dependency graph, news deduplication, forecast expiry, data-status view and corrections. Demonstrate no-change, new observation, source revision and broken-source updates. A normal refresh must not reinstall packages or redesign pages.

**Evidence:** repeat-run/idempotency tests, original timestamps retained, last-known-good preservation, update brief, no cross-snapshot partial publication, optional schedule templates disabled until authorized.

## G6 · Visual and accessible publication polish

Review actual browser renders at 360/390/768/1440, navigation with keyboard, reduced motion and no JS. Polish hierarchy, narrative rhythm, map legends, interactions, source controls, exports, empty states and mobile readability. Run assistive-technology/manual checks as available and distinguish them from automated scans.

**Evidence:** screenshots; actionable independent critique; corrected issues; accessible chart tables; responsive route journeys; performance/bundle report. A Lighthouse score alone is not sufficient.

## G7 · Independent publication audit

Independent reviewers open the sources supporting every headline and public current-data claim, recalculate important derived values, check geography/cutoff/cohort comparability and inspect exports. Audit political neutrality, rights, privacy, safety, source-chain dependence and uncertainty. Test the production build, not just development mode.

**Evidence:** completed acceptance matrix with actual evidence paths; no unresolved blocking findings; clear not-run/manual-review items. Never label an agent as a human scientist/editor.

## G8 · Portable release candidate and handoff

Produce the full and compact host profiles, deployment instructions, source/data/claim manifests, chart/data journalist exports, public coverage/freshness report, source code with lockfiles, a signed-off scope statement and release report. Test root and GitHub repository subpaths, direct deep links and refreshes. Count assets and measure output sizes.

**Evidence:** valid dist artifacts and ZIPs; release-gate report; package hashes; test results; preview paths; exact next update command; rollback instructions. Mark `candidate`, not `published`, until authorized.

## G9 · Authorized deployment

Only after the publisher explicitly authorizes the release hash and destination, deploy with least-privilege credentials. Verify actual URL, assets, deep links, data versions, citations and caching. Record deployment metadata and rollback. A schedule or public repo setting must never be activated silently.

**Evidence:** real deployment ID/URL, smoke-test result and publisher authorization record. If account access is absent, complete G8 and give exact manual steps, not a fictional URL.

## Completion standard

Deliver the best supported full local candidate, not merely a G2 demonstration. All feasible modules should be implemented through G8. Where evidence prevents coverage, expose a precise scope/gap report and still finish the reusable system. The user should receive something that can be hosted, audited and updated, not another set of promises.
